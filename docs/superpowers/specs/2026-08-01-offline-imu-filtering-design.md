# Offline IMU Roll/Pitch Filtering Design

## Goal

Add an offline tool to `horizontal_pkg` that weakly smooths the existing
roll/pitch CSV without changing ROS topics, PointCloud data, model inputs, or
the source CSV. Generate a checked-in comparison image that overlays the raw
and filtered signals.

## Scope

The runtime module is:

`src/Validator_pkg/horizontal_pkg/src/horizontal_pkg/imu_filtering.py`

The test module is:

`src/Validator_pkg/horizontal_pkg/test/test_imu_filtering.py`

The generated documentation image is:

`src/Validator_pkg/horizontal_pkg/docs/imu_roll_pitch_filtered.png`

The tool consumes the CSV generated by `imu_orientation_analyzer.py`. It does
not read a rosbag directly and does not subscribe to or publish ROS topics.

## Input and Output Contract

The input must contain `header_stamp_ns`, `elapsed_s`, `roll_deg`, and
`pitch_deg`. Required values must be finite. Rows must be strictly increasing
by `header_stamp_ns`; duplicate or reversed timestamps are rejected so the
filter cannot silently change measurement ownership.

The output preserves the input rows, order, timestamps, and original columns.
It appends exactly these columns:

- `roll_deg_filtered`
- `pitch_deg_filtered`

The output path must differ from the input path. Output is written through a
temporary file and atomically replaced so a failed run cannot leave a partial
CSV.

## Filtering

The default filter is a second-order Butterworth low-pass with a 4.0 Hz cutoff.
Because this is offline processing, filtering uses forward-backward
second-order-section filtering (`sosfiltfilt`) to avoid phase delay.

The source timestamps are not uniformly spaced. The tool therefore:

1. derives the representative sampling interval from the median positive
   `header_stamp_ns` difference;
2. rejects a cutoff at or above the derived Nyquist frequency;
3. linearly interpolates roll and pitch onto a uniform time grid;
4. applies the zero-phase Butterworth filter on that grid; and
5. linearly interpolates the filtered values back to the original timestamps.

The tool rejects input that is too short for stable forward-backward filtering.
It never fills non-finite values or silently drops rows.

## Command-Line Interface

The module is executable with the package module path:

```bash
/usr/bin/python3 -m horizontal_pkg.imu_filtering \
  --input-csv records/horizontal/imu_roll_pitch.csv \
  --output-csv records/horizontal/imu_roll_pitch_filtered.csv \
  --output-png src/Validator_pkg/horizontal_pkg/docs/imu_roll_pitch_filtered.png \
  --cutoff-hz 4.0
```

`--cutoff-hz` defaults to `4.0`. The CSV and PNG outputs are required and may
not overwrite their respective inputs.

## Comparison Image

The image contains two time-series panels sharing the elapsed-time axis:

- roll: raw `roll_deg` in gray and `roll_deg_filtered` in blue;
- pitch: raw `pitch_deg` in gray and `pitch_deg_filtered` in orange.

The title records `2nd-order Butterworth`, the actual cutoff, and `zero-phase`.
Axes include units, both panels include a legend and grid, and the image is
written atomically. The plot is documentation evidence only; it does not prove
that LiDAR compensation geometry has improved.

## Validation

Tests cover CSV contract preservation, known low- and high-frequency synthetic
signals, zero-phase behavior, irregular timestamp resampling, invalid values,
duplicate/reversed timestamps, Nyquist rejection, short input, and atomic
output behavior. Plot tests verify that a non-empty PNG is produced without a
display server.

After unit tests and Catkin tests pass, the tool runs on
`records/horizontal/imu_roll_pitch.csv`. Validation reports raw versus filtered
standard deviation and greater-than-4-Hz RMS for roll and pitch. The generated
PNG is inspected for dimensions and decoded successfully.

## Dependencies and Runtime Impact

Use the ROS Noetic system Python. Reuse the installed `numpy`, `scipy`, and
`matplotlib`; add their ROS/Ubuntu runtime declarations to `package.xml` if the
package does not already declare them. No online node, launch file, TF,
timestamp, LiDAR, BEV, inference, controller, or model-input interface changes.
